# Plano de redesign — TL-07 Resultado

## 1. Resumo em 5 linhas

1. [DECISÃO] A TL-07 compara alternativas por **exposição estimada**, tempo e caminhada; o mapa mostra a opção selecionada, e a escolha continua com a pessoa (`docs/app-map/04_telas/TL-07_resultado.md:3-7`).
2. [DECISÃO] O código já separa tocar no card (selecionar) do botão `›` (detalhes), desenha rotas com geometria válida, marca origem e destino e enquadra a rota selecionada (`src/mobile-app/src/components/resultado/resultado.tsx:70-90`; `src/mobile-app/src/components/mapa/MapaResultado.native.tsx:21-43`).
3. [HIPÓTESE] A maior melhoria é explicar cada opção com a sequência real de trechos, embarque e desembarque, sem criar dados novos, e deixar clara a ligação entre card e traço no mapa.
4. [HIPÓTESE] O painel fixo precisa de uma expansão de verdade; hoje o botão altera `expandido`, mas o painel mantém `flex: 1` e só o mapa muda de altura (`src/mobile-app/src/app/(app)/resultado/index.tsx:57-78`; `src/mobile-app/src/components/resultado/resultado.tsx:174-197`).
5. [EM ABERTO] O visual “rota acesa”, as cores dos selos, a fonte Atkinson e a atribuição do mapa ainda dependem de aprovação/definição; o prazo de código é a noite de 18/11 (`docs/app-map/07_design/tokens.md:3-37`; `docs/app-map/12_pendencias_e_lacunas.md:19,25`).

**Como ler:** P = pequeno, M = médio, G = grande, estimativas relativas de trabalho, não horas. “Sem nova” significa que a proposta cabe no React Native e nas dependências atuais. Toda frase de interface que não consta do catálogo é `[HIPÓTESE]` até aprovação do Lucas. Este arquivo é planejamento: nenhuma proposta abaixo foi implementada ou testada no aparelho.

## 3. TL-07 em profundidade

### 3a. Objetivo e hierarquia

1. [DECISÃO] Primeiro: **qual opção está selecionada e qual trajeto aparece no mapa**. Seleção se comunica pelo traço forte, barra lateral e texto “selecionada”; o halo proposto marca seleção, nunca exposição (`docs/app-map/07_design/tokens.md:11-14,39-46`; `src/mobile-app/src/components/resultado/resultado.tsx:77-81`).
2. [DECISÃO] Segundo: **como são as alternativas**: duração, caminhada, trocas, sequência de modos/linhas e saída prevista. Se há foco de menor exposição estimada, a API o põe primeiro; os outros focos continuam legíveis (`docs/app-map/04_telas/TL-07_resultado.md:114-125`; `src/mobile-app/src/consulta/reducer.ts:39-45`).
3. [DECISÃO] Terceiro: **limites dos dados** pela linha fixa “Sobre os dados”, em plano separado da exposição estimada. O indicativo curto não vira uma nota nem uma cor de alerta (`docs/app-map/01_decisoes.md:16,29`; `docs/05_regras_linguagem_etica.md:18-22`).
4. [HIPÓTESE] Ordem visual: cabeçalho compacto → mapa legível → lista de opções → rodapé fixo dos dados. A instrução de seleção aparece junto da lista e sai da leitura principal depois que a interação ficar evidente; validar com Lucas (`src/mobile-app/src/components/resultado/resultado.tsx:183-189`).
